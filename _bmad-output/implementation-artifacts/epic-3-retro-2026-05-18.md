## What Went Well

1. **The diagnostic canary is the epic's defining outcome.** Mother Sands turned an invisible
   pipeline into an observable one. The three-axis truth model (endpoint health / lifecycle /
   open-now) plus the four-layer coherence report (`endpoint file → heartbeat log → Oxigraph →
   GeoJSON → card`) gives the operator a way to pinpoint *where* a discrepancy enters the pipeline.

2. **The clean-slate pivot (3.4b) was the right call.** Rather than patch-on-patch through the
   3.x bug hunt, the epic wiped bulk VOW/RFF seeds, stood up a real canary endpoint at a public
   URL, and deprecated `seed_import.py`. This replaced guesswork with a controlled instrument.

3. **Schema/ontology rigor.** `core.ttl` + `crosswalk.csv` + `crosswalk.md` + `validate_crosswalk.py`
   operationalized the four-layer bundle model. Story 3.2-c reconciled code-vs-ontology vocabulary
   drift. The layered-namespace decision (under one canonical authority) was pinned.

4. **Test suites grew with the code.** ~49 → 83+ transformer tests, 49 hermetic canary tests, a
   regression-pin (xfail → pass) for the stuck-`seeded` bug, plus live network tests.

5. **Deferred work stayed well-routed.** Every code review appended tagged, dated entries to
   `deferred-work.md`; resolved items struck through with dates. Handoff hygiene held.

---

## What Was Hard / Challenges

1. **The pytest-vs-live gap bug class recurred all epic.** Story 3.3 named it explicitly: "the
   recurring Epic 3 bug lived in the gap between hermetic tests and the live pipeline." Four
   stories (3.1, 3.2, 3.4, 3.4b) each carried a "post-implementation fix (live testing)" section
   — scheduler lambda returning an un-awaited coroutine; `mom:lastUpdated` wiped on no-diff;
   stuck-`seeded`; 304 freezing `lastFetched`; canary unreachable from the container. Tests were
   green every time.

2. **Scope grew ~2×.** The epic that shipped (11 stories) does not resemble the epic that was
   planned (~4). Most additions were genuine discovery — but discovery this large means the
   original epic boundary was a hypothesis, not a plan.

3. **Code repeatedly outran its schema and docs.** Story 3.2-b shipped a `closed` lifecycle state
   the ontology never defined — a whole story (3.2-c) was needed to reconcile it. Story 3.5 found
   `schema:address` (ADR-015) vs `mom:address` (live transformer) incoherence.

4. **Idempotent SPARQL writes were a persistent hazard.** `DROP SILENT GRAPH` wiping
   `mom:lastUpdated` / `mom:lastFetched` shows up as a hazard note in 3.2, a live bug in 3.4, and
   a lessons table in 3.4b.

5. **Stale propagation is still live.** Per Nicolas: `make c-` injection lands in the canary JSON,
   but the change frequently stalls before map render — transformer logic goes stale, Oxigraph
   isn't updated/re-materialized, the pipeline doesn't reach map rendering, and browser cache
   isn't reliably hard-refreshed. The canary makes this *visible* now; the bugs themselves are
   not yet fixed.

---

## Key Insights

- **Epic 3 delivered the pipeline AND discovered the pipeline is not yet trustworthy end-to-end.**
  The canary is the win precisely *because* it surfaces that. The remaining bugs are, in Nicolas's
  words, "minor but blocking."
- **The stale-propagation bug is a class, not an instance.** It is distributed across transformer
  → Oxigraph write → GeoJSON materialization → map render → browser cache. No single fix closes it.
- **Story 4.3's inspection panel (RAW / INGESTED / DISPLAYED) is conceptually the per-space
  coherence report.** Epic 4 mission control is the right home for the bug-sweep: the dashboard
  that finds each stale-propagation bug and the fix for it ship together.
- **The pytest-vs-live gap will keep recurring until Definition-of-Done forces a live check.**

## Addendum — Party-Mode Roundtable Deep-Dive (2026-05-18)

A multi-agent roundtable (Winston/Architect, Amelia/Dev, John/PM, Mary/Analyst) deepened the
retro. Outcomes:

- **Root cause, named:** the system is a five-stage cache chain (endpoint JSON → SQLite →
  Oxigraph → GeoJSON → browser) with no propagation contract — every retro bug lived at a seam
  where a stage stamped its own "now." The fix is one `observed_at` token minted once at fetch
  and carried unchanged through every stage.
- **Test diagnosis:** the green-suite-while-pipeline-broke fact = all tests mocked the
  integration seams. The two retro DoD gates were necessary but insufficient; the real fix is
  temporal / two-cycle / real-triplestore tests.
- **Decision — new pre-Epic-4 epic created: Epic 3.5 "Freshness Propagation Contract"**
  (stories 3.6–3.10, strictly linear, each gated by a real-seam test; see `epics.md`). This IS
  the multi-cache fix and the path to demo v0.2. Built standalone before Epic 4.
- **Epic 4 done-condition (from John):** a stale space visibly renders stale against a real
  endpoint; a fresh one does not. Owed before Epic 4 story one: numeric staleness thresholds.
- **Ontology (from Mary):** the data layer has a source of truth (endpoint JSON) + a reconciler
  (heartbeat); the ontology layer has neither. Add versioning + a conformance check so
  fog-of-war exploration stops generating reconciliation-tax stories.
- **Deferred:** `spaces.geojson` payload-slimming — logged in `deferred-work.md`, Epic 5+.

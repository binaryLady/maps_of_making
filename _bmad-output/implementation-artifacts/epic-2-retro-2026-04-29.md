## What Went Well

1. **Epic restructuring worked** — collapsing old 2.1–2.4 into one vertical slice prevented premature layering. The coordinator gesture (URL → register → card) shipped as a coherent unit.

2. **Real-world validation happened** — the SKILL.md dual-validator exercise with openfab.jsonld exposed real gaps (SpaceAPI cliff, `mom:dynamicState` naming collision, AI tag vocabulary). This is the "walk the talk" discipline from Epic 1 retro.

3. **Deferred work is well-routed** — deferred-work.md has 40+ items all tagged with `→ Epic N` or `→ Story X.Y`. Future story creation can triage rather than rediscover.

4. **Mobile layout shipped cleanly** — 2.6 was zero-debt (no mobile items deferred). 39-issue code review, all triaged or patched.

5. **Pydantic schema foundation (2.7)** — dual-shape JSON-LD pattern established; validate_dual.py; test fixture at `web/test-fixtures/openfab.jsonld`. Epic 3+ has a validation baseline.

---

## What Was Hard / Challenges

1. **Story 2.2 was never formally executed** — its code landed through 2.1 and 2.7, but the story file was never updated to `done` and no dev notes were written. Status contradiction is a process gap: sprint-status was updated without the story file being closed.

2. **Data lifecycle not fully visible end-to-end** — what gets stored (rawContent, description, openingHours) vs. what is displayed (Zone 2 data card, Zone 3 raw source) vs. what is queryable (SPARQL) was never documented as a unified view. Bugs and confusion arise at the gaps between layers.

3. **Admin routing complexity** — two-layer nginx (gateway + maps-nginx) creates non-obvious auth + proxy_pass interaction. The `proxy_pass http://maps-nginx/admin/` URI rewrite pattern is subtle; required a fix commit (df94b84) and still has open questions about deployment state on VPS.

4. **Zone 3 visibility rules are implicit** — desktop-only AND non-seeded status gate is only in the code, not documented anywhere. Will confuse future devs and makes it hard to test.

5. **Story file / sprint-status divergence** — two sources of truth about story status with no enforced sync. Happened twice in this epic (2.2 and possibly 2.7 had multiple status updates).

---

## Key Insights

- **The card data lifecycle is the core product loop** for Epic 3+: coordinator registers URL → backend fetches + stores (rawContent, description, hours) → SPARQL SELECT reads back → GeoJSON materializes → UI card renders. Every epic will touch this chain. It needs to be documented explicitly as a data flow, not left implicit in code.
- **Zone visibility rules need to be surfaced as a spec**, not just code guards. Zone 3 being desktop-only and confirmed/broken-only is a product decision that should be documented (deferred to Epic 5 but should be noted).
- **VPS deployment state is invisible** — it's unclear at any given time whether local git changes have been deployed to the VPS. A `make status` or deploy-diffing mechanism would reduce confusion.
